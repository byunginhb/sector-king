# 섹터 매치 단기 베타 — 조기 공개

기준일: 2026-11-18 UTC. 사용자는 기존 주간 대진과 분리된 단기 베타로 접수·정산 검증을 앞당기는 안을 승인했다. 11/18 운영 DB 재조회에서 기존 라운드의 참여자와 정산은 각각 0건이었다.

**현재 상태: 접수 보류.** `enabled:false`다. 과거 가격의 정규장 종가 정의를 확인하지 못해 자동 게시를 활성화하지 않았다. 아래 날짜는 준비한 후보 일정이며 개시 약속이 아니다. 가격 기준을 해결하기 전에 마감이 지나면 이 후보를 게시하지 않는다.

11/19 정규장 10:00~16:30은 [KRX 공식 수능일 거래시간 공시](https://kind.krx.co.kr/external/2026/11/05/000141/20261105000216/99303.htm)로 재확인했다. 접수 개시는 미래 가격이나 과거 시간으로 꾸미지 않는다. 모든 실제 기준 종가가 준비된 시각 이후로 저장한다.

기존 `kr-2026-11-16`은 마감·원본·11/20 정산을 유지한다. 주간 대진의 종료를 앞당기거나 원장을 수정·삭제하지 않는다. 단기 베타는 한 거래일의 가격 변동률을 비교하며 주간 기록이나 배당 포함 투자 성과가 아니다.

## 운영 변경

- 실제 설정은 [`config/weekly-match-pilot.json`](../../../../config/weekly-match-pilot.json)과 기존 [`config/weekly-match.json`](../../../../config/weekly-match.json)을 각각 사용한다. 비활성 `weekly-match-next.json`은 여전히 자동 소비하지 않는다.
- 기존 `weekly-match.yml`에 명시적인 `weekly`·`pilot` matrix 두 항목을 두고 `fail-fast:false`로 격리한다. daily 예약은 `09:05 UTC`다. 그룹 이름은 이전 실행과의 상호 배제를 위해 기존 값을 유지한다.
- 감사 경로는 `.weekly-match-audit/weekly/`, `.weekly-match-audit/pilot/`로 분리한다. baseline artifact는 기존처럼 라운드 ID로 이름을 붙여 과거 원본 복원이 호환된다.
- operation artifact는 `weekly-match-operation-{weekly|pilot}-{run_id}-{attempt}`, settlement는 같은 방식의 라운드별 접두어를 사용해 같은 실행 안에서 충돌하지 않는다.
- 게시된 원본 불변, 신뢰 workflow·main·저장소 검증, 마감 재확인, 확정 결과 덮어쓰기 방지, 결측 보류와 7일 무효 규칙은 유지한다. 새 스키마·권한·인증 공급자를 추가하지 않는다.
- 전역 메뉴와 섹터 화면에 `섹터 매치` 베타 진입을 제공한다. 페이지의 비교 기간 설명은 단기·주간 대진에 모두 맞추고 `noindex`와 sitemap 제외는 유지한다. 실제 접수 상태는 공개 API의 게시 기록으로만 표시한다.

[GitHub 공식 문서](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule)에 따라 예약 실행은 지연되거나 누락될 수 있다. 18:05는 예약 시각이며 실제 개시 보장이 아니다. 기존 도구·계정으로 등록된 예약과 실행 상태를 확인하고, 필요 시 `gh workflow run weekly-match.yml --ref main`으로 재실행한다. 미게시 상태로 접수 마감이 지나면 날짜를 이동하지 않고 중단한다.

## 데이터·참여 검증

공식 DART 212건·KIND 248건 및 12종목별 관련 전문, 현재 거래정지 현황을 검토했다. 확인 시점에 베타 기간 안의 비교 불가능한 분할·병합이나 거래정지는 찾지 못했다. 신한 자기주식 소각 변경상장은 11/18 기준 종가 전, 하나·우리 변경상장은 11/20으로 베타 종료 후다. 미래 공시 부재를 보장하지 않으며, 게시 시 실제 기준 일봉의 날짜·양수 거래량·통화·티커·원본 hash를 추가 검증한다. 종료일 기준값 변경·split·결측이면 기존 보류 규칙을 따른다.

과거 11/13 기준 원본과 실제 11/17 종료 일봉 12개로 격리 재현했다. 서비스 `calculateSettlement`와 별도 유리수 손계산은 은행 -0.381907%, 조선 -3.282732%, 은행 우세로 일치했다. 이는 현재 라운드·단기 베타의 운영 결과가 아니다. 결측·기업행사·null 가격·null 거래량은 보류, 정확히 종료+7일부터 무효이며 원본·기존 config hash가 유지됐다.

### 가격 원천 확인 장애

기존 Yahoo 일봉의 `quote.close`를 재현했으나 KRX 정규장 종가와의 대조는 완료하지 못했다. [신한증권 공식 주가정보](https://open.shinhansec.com/new_ir/info/info_03_02.jsp)의 동일 신한지주(055550) 가격은 11/16 90,900원·11/17 87,300원, Yahoo는 각각 90,700원·87,500원이다. 신한증권 표는 열을 “가격”으로만 표시하고 세션·수정 여부를 정의하지 않으므로 Yahoo 오류로 단정하지 않는다. 서로 다른 기준을 비교했을 가능성이 남아 있다.

KRX 공개 통계 요청은 자료를 받지 못했고, [공식 일별 시세 API](https://openapi.krx.co.kr/contents/OPP/USES/service/OPPUSES002_S2.cmd?BO_ID=JvJFzlAENzZlPBDNGAWC)는 AUTH_KEY가 필요하다. 인증을 우회하거나 비밀값을 요청·기록하지 않았다. 운영자가 공식 원장의 동일 종목·날짜·정규장 종가와 대조하고, 차이가 나면 원인을 해결한 뒤 활성화한다. 기존 주간 정산의 가격 해석에도 같은 한계가 있으며 이번 재현을 독립 원장 검증으로 취급하지 않는다. 조사 원본과 개별 차이는 로컬 `.harness/weekly-pilot-20261118/data/`에 보관한다.

실제 사용자의 로그인·본인 기록은 기존 인증을 사용한다. 격리 세션 fixture의 저장·변경·잠금 검사와 실제 Google 로그인 성공을 구분한다. 사용자가 직접 확인하기로 했으며 다음 정상 접수 중 저장 → 새로고침 유지 → 반대편 변경 저장을 확인한다. 운영에 가짜 사용자나 선택을 만들지 않는다.

## 중지·후속 확인

새 게시를 중지하려면 베타 manifest의 `enabled:false`만 커밋·푸시한다. 기존 주간 대진의 처리는 유지한다. 이 설정은 수집·게시·정산 호출을 중지하며, 이미 게시된 대진의 사용자 접수 마감을 바꾸지는 않는다. 코드 롤백은 변경 커밋을 revert하고 원장을 보존한다. 보존 원본은 90일 만료 전 운영 보관 여부를 판단한다.

예약 등록, 첫 실행, 실제 게시, 실제 선택 저장, 실제 정산을 각각 확인한다. 아직 발생하지 않은 미래 단계를 완료로 보고하지 않는다. 배포 완료와 disabled 실행 확인은 베타 게시 완료를 뜻하지 않는다. 활성화 전에는 가격 원장 대조, 게시 시 추가 공시·실제 기준 종가 재확인, 정상 접수 중 본인 선택 저장 검증이 남는다.
