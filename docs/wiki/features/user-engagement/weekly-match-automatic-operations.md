# 섹터 매치 자동 운영

2026-11-26 사용자 승인 범위: 주간 대진 생성·검수·게시·정산·기존 보상 연결, GitHub 저장과 푸시. 자동 운영 설정은 [`config/weekly-match-automation.json`](../../../../config/weekly-match-automation.json)이다. 첫 대상은 `kr-auto-2026-11-30`이며 실제 미래 종가가 준비되기 전에는 게시하지 않는다.

## 운영 주기와 대진 생성

기존 [Weekly Match workflow](https://github.com/byunginhb/sector-king/actions/workflows/weekly-match.yml)가 `main`에서 매일 **09:17·13:47 UTC / 18:17·22:47 한국시간**에 실행한다. 한국시간은 일광절약시간이 없다. GitHub 예약은 [지연·누락될 수 있으므로](https://docs.github.com/en/actions/how-tos/troubleshoot-workflows) 이 시각을 실제 개시·정산 완료 시각으로 약속하지 않는다.

1. `automate_weekly_match.py`가 다음 접수 마감이 아직 오지 않은 월요일을 계산한다. 첫 주는 11/30이고 이후 주는 날짜를 자동 생성하므로 매주 설정을 편집하거나 커밋할 필요가 없다.
2. 대진 구성은 기존 한국 은행7·조선5 템플릿을 재사용한다. 기준일은 직전 금요일, 선택 마감은 월요일09:00, 종료일은 같은 주 금요일18:00 한국시간이다. ID는 `kr-auto-YYYY-MM-DD`로 고정한다.
3. 공개된 이전 자동 대진 중 미확정인 것도 같은 실행 계획에 포함한다. 새 주의 개시가 과거 `pending` 재확인을 대체하지 않는다. 확정 결과와 비활성 수동 후보는 다시 처리하지 않는다.
4. 생성한 manifest와 실행 계획은 run별 artifact로 보관한다. 기존 수동 manifest·원장·지난 비활성 후보는 바꾸지 않는다. 템플릿의 `enabled:false`는 원본 후보의 상태이며 자동 운영 전체 스위치는 별도 설정이다.

첫 주의 계획은 **11/27 기준 종가 → 11/30 09:00 마감 → 12/4 종료 종가**다. 기준 종가를 읽을 수 있는 11/27 18:00 이후에만 실제 검수·게시를 시도한다. 마감이 지나면 해당 주를 다시 열거나 날짜를 늘리지 않고 다음 미래 주를 계획한다.

## 자동 검수와 실패 처리

게시 직전과 정산 때 `weekly_match_checks.py`가 다음 조건을 확인한다.

- `holidays==0.109`의 **XKRX 금융 달력**으로 기준일과 예정 월~금 거래일을 검사한다. 공휴일·대체휴일·노동절·연말휴장이 포함된 주는 보류하고 날짜를 임의 변경하지 않는다. [원본 달력](https://github.com/vacanza/holidays/blob/v0.109/holidays/financial/korea_exchange.py)과 [KRX 기본 규정](https://global.krx.co.kr/contents/GLB/06/0602/0602020204/GLB0602020204T1.jsp)을 함께 따른다.
- [KRX 공지](https://open.krx.co.kr/contents/OPN/05/05000000/OPN05000000T1.jsp)의 현물 휴장·시간 변경과 [KIND 현물 거래정지](https://kind.krx.co.kr/investwarn/tradinghaltissue.do?method=searchTradingHaltIssueMain)를 재조회한다. 정상 주말 때문에 비교 주 전체를 막지는 않지만, 확인되지 않은 오래된 응답을 신선한 자료로 취급하지 않는다.
- 12개 발행인의 DART·KIND 공시를 기준일/검수일 중 이른 날 이전366일까지 전건 페이지 조회한다. 총건수·페이지·중복·종목 식별을 검사한다. 정상적인 0건과 오류/잘못된 페이지를 구분한다. 원천당20페이지 상한을 넘으면 보류한다.
- 분할·병합·합병·감자·증자·상장폐지·현물 정지·변경상장처럼 가격 단위나 구성 비교에 영향을 주는 사건은 **구조화된 실제 사건일**과 비교 기간을 대조한다. 문서 작성일이나 본문 속 임의의 최신 날짜로 안전 판정을 내리지 않는다. 모호하면 보류한다. 단주 자기주식 소각·현금배당 지급·IR·주식선물 공시는 현물 분할·병합과 구분한다.
- 종가는 기존 Yahoo 무보정 일봉과 Npay `regularMarketClosingPrice`를 대조한다. [정규장 종가와 애프터마켓 포함 최종가](https://help.pay.naver.com/faq/content.help?faqId=18245)를 혼용하지 않는다. 필수 종목·날짜·통화·양수 거래량·기준가 변경·split 검사도 유지한다.

공식 검수 원본은 압축한 원래 bytes와 URL·요청조건·수집시각·SHA256으로 저장한다. `review.json` 원본과 runner의 `verdict.json` 판정을 분리해, 잘못된 검수 보고서도 원본을 보존하면서 안전하게 거부한다. **검수 artifact → 기준/정산 가격 artifact → API** 순서로 처리한다. 저장에 실패하면 API를 호출하지 않는다. 게시 승인은 검수 후30분 이내에만 사용할 수 있다.

게시 검수 실패는 `review-blocked`이며 새 라운드를 만들지 않는다. 정산 검수 실패는 전체 구성 종목을 결측으로 보존한 채 기존 서버 규칙으로 `pending`, 종료7일 후에도 미확인이면 `void`로 처리한다. 종목 제외·비중 재분배·가짜 승패는 만들지 않는다. 안전한 보류/무효 기록에 성공해도 **검수 실패 자체는 Actions 실패·알림으로 남긴다.**

대진당 실행은15분, 계획은10분으로 제한한다. 스크립트의 즉시 반복 재시도는 없으며 같은 날 두 번째 예약이 제한된 재확인이 된다. 게시 마감 뒤에는 새 게시를 중단하고, 정산은 기존7일 만료 규칙으로 종료한다. 독립 대진의 실패는 다른 라운드를 취소하지 않는다.

## 정산·보상과 재실행

기준 원본은 라운드 ID로 분리한 trusted artifact에서 복원한다. 저장소·main·해당 workflow·실행 이벤트·SHA를 확인한 원본만 허용한다. 게시된 라운드는 당시 구성·가격·시간을 계속 사용하므로 이후 템플릿 변경이 과거 결과를 바꾸지 않는다. 원본이 없으면 재생성하지 않고 실패 처리한다.

게시/정산 타임아웃 뒤에는 동일한 원본을 재사용한다. 동일 라운드 ID와 기존 DB 멱등 처리·잠금·최종 결과 보호를 유지한다. 이미 확정된 승리·동률·무효를 자동으로 덮어쓰지 않는다.

보상은 별도 지급 작업 없이 기존 본인 선택 원장과 최신 정산에서 계산한다. **정상 첫 선택은 첫 참여 배지, 적중은1점, 실패는0점**이다. 동률·무효·미확정은 적중 점수에서 제외한다. 시즌은 종료일 기준 한국시간 월이며, 최신 정정 시 점수와 카드도 다시 계산된다. 반복 조회나 작업 재실행으로 점수가 누적 발급되지 않는다. 현금·유료 이용권·외부 결제 보상은 없다.

공개 설정에 동의한 사용자만 기존 월별 순위에 표시한다. 개인 API의 인증·본인 접근·private/no-store 경계는 유지한다. 실제 사용자 OAuth와 정상 접수 중 저장/변경 검증은 격리 자동 검사와 별개다.

## 알림·중지·복구

실패하면 Actions annotation/summary와 저장소의 **`[섹터 매치 자동 운영] 확인 필요` 이슈 하나**에 실행 링크를 남긴다. 기존 저장소는 공개 상태이며 알림에도 공개 실행 링크와 단계 상태만 넣는다. 같은 제목의 열린 이슈를 갱신하고, 실제 검수를 통과한 게시·정산을 포함한 정상 실행이 확인돼야 닫는다. 단순히 다음 기준일을 기다리는 상태를 복구로 표시하지 않는다. 여러 대진 중 마지막 작업이 대기 상태라면 이슈 종료는 다음 검수 성공까지 늦춰질 수 있다. 가격 원장·사용자 정보·비밀값을 알림 본문에 넣지 않는다. 실제 이메일/웹 알림 수신은 사용자의 [GitHub 알림 설정](https://docs.github.com/en/actions/concepts/workflows-and-actions/notifications-for-workflow-runs)에 달려 있으며 별도 메일·Slack 공급자를 추가하지 않는다.

- 자동 대진 중지: `config/weekly-match-automation.json`의 `enabled:false`를 커밋·푸시한다. 기존 수동 라운드 설정은 각각의 enabled를 따른다.
- 전체 workflow 중지: `gh workflow disable weekly-match.yml`.
- 복구/재실행: 원인을 수정한 뒤 `gh workflow run weekly-match.yml --ref main`. 먼저 보존 artifact와 공개 상태를 확인한다. 실행 중단만으로 사용자 마감이나 원장을 수정하지 않는다.
- 되돌리기: 이번 자동화 변경을 revert하고 원장을 유지한다. 확정 결과를 삭제하거나 운영 데이터를 되돌리는 작업은 포함하지 않는다.

artifact는90일 보관한다. 장기 원본 보존이 필요하면 만료 전에 별도로 보관한다. 원본 만료를 검증 완화나 재생성으로 우회하지 않는다. GitHub Actions 기존 계정·요금 범위를 사용하며 무료 한도를 무제한이나 과금 자동 차단으로 표현하지 않는다.

## 검수의 한계와 운영 확인

자동 공시 검수는 명시된 조회기간과 지원하는 사건 유형·공식 페이지 구조에 한정된다. 더 오래전에 발표된 미래 사건, 새 법정 휴일이나 특이한 공시 형식의 부재를 보증하지 않는다. 확인한 범위의 모호한 사건·응답 변경·자료 장애는 보류하며, 실제 가격의 split·기준가 변경·불일치도 별도로 검사한다. Npay 가격 대조는 최근60개 일봉 범위이고, KRX 원장을 직접 내려받았다고 주장하지 않는다. KIND 거래정지 목록은 검수 당일 한국시간 날짜를 요구하므로 주말에 직전 거래일 표기만 제공되면 게시를 보류한다.

일일 운영에서는 실행·검수 원본·접수 링크와 열린 사고 이슈를 확인한다. 주간에는 기존 발견→진입→정상 저장→결과 확인→재참여 지표를 검토한다. 이번 작업은 새 광고·홍보 게시·메일 발송·성과 수치 생성을 활성화하지 않는다.

검사와 실행 증거는 로컬 `.harness/weekly-auto-20261126/`에 보관한다. 코드·격리 cycle 통과, 원격 workflow 실제 실행, 실제 신규 게시·사용자 참여·미래 정산을 각각 구분해 보고한다.
