# 주간 섹터 매치 — 최소 설계와 데이터 확인

> 확인일: 2026-11-07 · 상태: **설계·로컬 데이터 검증, 미출시**
> 범위: 후보 E01의 4순위 작업. 실제 경기·사용자 접수·시즌 순위는 구현하지 않았다.

## 제안하는 첫 경기

국내 시장의 두 섹터를 같은 조건에서 비교한다. 대진 예시는 한국 은행(`korea_banks`) 대 조선(`korea_shipbuilding`)이며, 실제 출시 대진으로 확정한 것은 아니다.

- 계정당 라운드 선택 하나. 접수 기간에는 수정 가능, 서버 마감 시각 이후 수정 불가.
- 기준일은 직전 주의 마지막 **거래일**, 종료일은 이번 주의 마지막 **거래일**이다. 금요일 날짜를 일괄 사용하지 않는다.
- 직전 기준일 종가 확정 후 접수하며, 이번 주 첫 거래 세션 개장 전에 마감한다. 거래소 달력과 `Asia/Seoul` 시간을 기준으로 정확한 UTC 마감을 저장한다.
- 접수 시작 전에 두 섹터의 국내 구성 종목과 산식을 고정한다. 현재 분류를 과거 라운드에 소급 적용하지 않는다.
- 고정 비중 가격 변동률은 각 종목의 `종료 가격 / 기준 가격 - 1`을 동일 비중으로 평균한다. 시총 변화액·실제 순매수·배당 포함 총수익률과 구분한다.
- 비교값은 퍼센트포인트 소수 여섯 자리로 반올림해 동률을 판단하는 안을 제안한다. 적중 1점, 실패 0점, 동률·무효는 유효 참여 수에서 제외한다.
- 기본 기록은 본인만 조회한다. 공개 순위·공유는 별도 닉네임·명시적 동의가 선행한다. 현금성 보상은 없다.

## 필요한 저장 계약

운영 스키마·마이그레이션이 아니라 다음 구현의 검토안이다. 기존 Supabase 사용자 저장소를 재사용하고 시장 SQLite는 읽기만 한다.

| 기록 | 필요한 정보·불변 조건 |
| --- | --- |
| 라운드 | 대진, 구성 종목/비중 스냅샷, 거래소, 접수·마감·기준·종료 시각, 산식 버전, 상태 |
| 선택 | 사용자·라운드 유일 키, 선택한 쪽, 서버 제출 시각. 서버/DB에서 마감 검증. 본인 읽기·허용 기간 수정 |
| 정산 | 라운드·버전 유일 키, 실제 기준/종료 가격·출처·시각, 양측 값, 승패·보류/무효 사유, 확정 시각 |
| 공개 결과 | 허용된 결과·닉네임만 반환하는 별도 응답. 개인 프로필·이메일·비공개 메모를 직접 공개하지 않음 |

클라이언트가 점수·마감·사용자 ID를 확정하지 않는다. 정산 재실행은 같은 입력이면 같은 결과여야 하며, 수정 데이터로 재정산할 때는 새 버전을 기록한다. 취소·보류·정정이 시즌 점수와 공유 결과에도 일관되게 전파되어야 한다.

## 로컬 데이터 관찰 결과

`data/hegemony.db`를 SQLite `mode=ro`·`query_only=ON`으로 조회했다. 네트워크 수집·DB 쓰기·운영 접수는 하지 않았다.

- 스냅샷 범위: 2025-07-01~2026-11-05, 351개 서로 다른 날짜, 602개 티커.
- 현재 국내 구성: 한국 은행 7종목, 조선 5종목.
- 아래 네 날짜 구간에서 현재 구성 12종목의 양 끝 날짜 양수 가격은 모두 조회됐다. 유한한 값으로 같은 티커의 가격 비율 평균을 재계산했다.

| 기준 날짜 → 종료 날짜 | 한국 은행 가격 변동률 평균 | 조선 가격 변동률 평균 | 가격 조회 |
| --- | --- | --- | --- |
| 2026-10-23 → 2026-10-30 | +1.232258% | -9.537164% | 각 7/7, 5/5 |
| 2026-10-16 → 2026-10-23 | -4.872651% | -9.784708% | 각 7/7, 5/5 |
| 2026-10-09 → 2026-10-16 | -2.822464% | -6.530304% | 각 7/7, 5/5 |
| 2026-10-02 → 2026-10-09 | -3.585944% | -9.496739% | 각 7/7, 5/5 |

이는 **가격 조회와 산술 계산 가능성 검사**다. 날짜를 금요일 간격으로 뽑았으며 거래소 달력과 유효 거래 여부를 검증하지 않았다. 위 값은 검증된 실제 주간 성과·투자 수익률·모의 대회 결과가 아니다. 현재 구성 종목을 사용했으므로 과거 구성 기반 백테스트도 아니다.

## 출시 전에 남은 필수 확인

1. 수집 가격의 분할·병합 조정 방식과 배당 미포함 여부를 원천·수집 코드·표본으로 검증한다.
2. 한국 거래소 달력과 유효 종가를 확인한다. DB에 특정 날짜 행이 있다는 사실만으로 실제 거래일·거래된 가격이라고 판단하지 않는다.
3. 상장폐지·거래정지·가격 결측을 임의 제외하면 비중이 달라진다. 첫 버전은 해결 전 정산 보류, 공지된 유예 기간 후 무효로 처리하는 안을 검토한다.
4. 기준·종료일 이전에 공개되지 않은 데이터가 채점 입력에 섞이지 않도록 데이터 도착·확정 시점과 구성 스냅샷을 저장한다.
5. 휴장·지연·중복 제출·마감 직전 경합·재정산의 자동 테스트와 격리된 DB 검증을 수행한다.
6. 운영 담당·정산 실행 환경·타임존·중복 키·재시도 상한·실패 알림·중지 방법을 확정한 뒤 실제 첫 접수와 정산을 검증한다.

따라서 이번 결과는 “접수 기능을 바로 운영해도 된다”는 판정이 아니다. 위 필수 확인이 끝나면 `접수 → 잠금 → 정산 → 내 결과` 순서의 구현을 이어갈 수 있다.
