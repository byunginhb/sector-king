# 섹터 매치 — 종가 검증과 다음 접수 순서

기준일: 2026-11-26 한국시간. 기존 대진의 선택·정산 원장을 변경하지 않고 다음 접수를 준비한다.

## 1. 첫 정산과 가격 기준 확인

`kr-2026-11-16`의 보존 기준·종료 입력 12종목을 원본 응답 및 공개 결과와 대조했다. 서비스 정산 함수를 호출하지 않는 별도 유리수 계산에서도 은행 **-3.212589%**, 조선 **-7.243264%**, 은행 우세가 재현됐다. 운영 최신 결과는 버전2이고 실제 참여는 0명이다.

기존 신한지주 가격 차이는 같은 날의 **정규장 종가와 최종 체결가**를 비교하면서 발생했다. [Npay 공식 안내](https://help.pay.naver.com/faq/content.help?faqId=18245)는 종가를 정규장 종료 가격, 최종가를 애프터마켓 포함 최종 체결가로 구분한다. 실제 종목 화면도 `regularMarketClosingPrice`와 `closingPrice`를 각각 이 두 항목에 연결한다.

| 신한지주 | 정규장 종가 · Yahoo와 일치 | 최종 체결가 · 기존 신한증권 표와 일치 |
| --- | ---: | ---: |
| 11/16 | 90,700원 | 90,900원 |
| 11/17 | 87,500원 | 87,300원 |
| 11/20 | 86,200원 | 86,300원 |

은행7·조선5의 11/13·11/20 **24개 가격 모두 Npay 정규장 종가와 일치**했다. 이 중 21개는 최종 체결가와 달랐다. Npay의 [신한지주 실제 공개 응답](https://m.stock.naver.com/front-api/stock/domestic/price/list?code=055550&size=60)과 공식 화면 정의를 대조한 결과이며, KRX 원장을 직접 내려받았다는 뜻은 아니다. 이 응답의 조회 기간은 시간이 지나면 이동한다.

## 2. 수집기의 재발 방지

`scripts/weekly_match.py`는 기존 Yahoo 무보정 일봉을 유지하면서 같은 종목·날짜의 Npay `regularMarketClosingPrice`와 비교한다. 최종가·수정주가로 대체하거나 두 가격을 평균내지 않는다.

- 누락·중복 날짜, 실패 응답, 양수가 아닌 가격·거래량, 종가 불일치면 수집에 실패한다. 게시 단계에서는 새 대진을 만들지 않는다.
- 정산 단계에서는 기존 runner가 해당 종목을 결측으로 남긴다. 전체 구성과 비중을 유지하고, 기존 규칙대로 보류 또는 종료 7일 후 무효로 처리한다.
- 성공한 수집의 감사 자료에는 두 원천의 URL·수집 시각·응답·SHA256을 보관한다. 서버 가격 DTO와 기존 Yahoo source 계약은 바꾸지 않는다.
- Npay 거래량은 통합 누적 기준이므로 Yahoo 거래량과 숫자 일치를 요구하지 않는다. 양수 거래 여부만 확인하고 기존 Yahoo 거래량을 유지한다.
- 공개 API의 최근 60개 일봉 범위를 사용한다. 날짜가 범위를 벗어나면 검증에 실패하며 다른 가격으로 보충하지 않는다. 이 공개 웹 경로의 형식 변경·장애도 게시 보류 사유다.
- 검증 실패 시 기존 runner의 실패 감사에는 예외 종류가 남으며, 실패한 두 응답의 전체 비교 값은 보존되지 않을 수 있다. 값을 추정하지 말고 원천을 재확인한다.

collector와 runner Python 21개, 대진 앱 단위·API·UI 88개와 production build가 통과했다. build는 시장 DB 다운로드 없이 `pnpm exec next build`로 실행했다. 실제 새 collector로 12종목·24종가를 읽기 전용으로 재조회했으며 서버 ingestion은 호출하지 않았다. workflow도 collector와 runner 검사를 함께 실행한다.

## 3. 미래 대진 준비 → 게시

지난 11/19·11/23 후보를 다시 열지 않는다. 다음 검토 대상은 **11/27 기준 종가 → 11/30 09:00 접수 마감 → 12/4 종료 종가**의 한국 은행 vs 조선이다. 종목 구성은 기존 은행7·조선5를 유지한다.

신규 후보는 [`config/weekly-match-2026-11-30.json`](../../../../config/weekly-match-2026-11-30.json)에 `enabled:false`로 보관한다. 지난 후보와 현재 활성 설정은 보존했다. 아직 발생하지 않은 11/27 종가는 넣지 않는다. 미래 후보의 날짜는 운영 일정 확정이나 자동 게시 예약이 아니다.

11/26 현재 공식 DART263건·KIND305건의 목록과 관련 DART전문47건을 검토했다. 현재 유가증권 거래정지26종목에 후보12종목은 없다. [KRX 기본 거래시간·휴장 규정](https://global.krx.co.kr/contents/GLB/06/0602/0602020204/GLB0602020204T1.jsp)과 10/1~11/26 공지 검색 범위에서는 11/19 수능일 외 거래시간 변경이나 후보 기간 휴장 공지를 찾지 못했다. 후보의 정상 거래시간은 기본 규정·요일·이 현재 공지 범위에서 판단한 것이며 미래 긴급 변경의 부재를 보장하지 않는다.

기준일에는 [기업은행의 기취득 자기주식2주 소각 예정](https://dart.fss.or.kr/dsaf001/main.do?rcpNo=20261023800699)이 있어 게시 직전 정정·변경상장과 실제 기준가를 다시 확인한다. 원문은 자본금 감소 없는 단주 소각이며 잔존 주식의 분할·병합과 구분한다. 신한지주의 11/27 현금배당 지급은 가격수익률에 더하지 않는다. 12종목별 근거와 확인 범위는 로컬 `calendar/report.md`에 보존했다.

게시 순서는 다음과 같다.

1. 11/27 18:00 한국시간 이후 새 공시·거래 일정과 실제 기준 종가 12개를 재확인한다. 두 원천 대조가 모두 통과해야 한다.
2. 기존 결과가 확정됐음을 다시 확인한 뒤 검토한 manifest를 활성 설정으로 전환한다. 후보 파일은 workflow가 자동 소비하지 않는다.
3. 기존 workflow로 기준 원본 선저장 → 게시 → 영수증 → 공개 API의 구성·일정 일치를 확인한다. 마감까지 게시되지 않으면 중단하고 날짜를 자동 연장하지 않는다.
4. 12/4 이후 보존 기준가와 종료 종가로 정산하고 공개 결과를 다시 대조한다. 확정된 기존 라운드는 자동 재계산으로 덮어쓰지 않는다.

GitHub 예약은 지연될 수 있다. 최근 11/25 실행은 성공, 11/24는 prepare 단계 실패였다. 이전 실패 로그가 예외 종류만 남겨 원인을 확정할 수 없으므로 정산 장애나 가격 장애로 단정하지 않는다. 새 게시 때는 실제 실행과 영수증을 확인한다.

## 4. 정상 참여와 재참여 확인

접수 중인 새 라운드가 생긴 뒤 사용자 계정으로 Google 로그인 → `/weekly-match` 복귀 → 본인 선택 저장 → 새로고침 후 유지 → 반대편 변경 → 재조회를 확인한다. 실제 참여 기록으로 남기며 가짜 사용자·라운드를 운영에 만들지 않는다.

그 다음 확정 결과의 개인 점수·공유 카드·공개 동의한 순위를 확인한다. 이미 구현된 기능을 중복해서 만들지 않는다. 격리 테스트 통과를 실제 OAuth 성공이나 참여 실적으로 표시하지 않는다.

대상은 한국 주식 섹터를 비교하는 기존 대시보드 방문자다. 기존 홈 카드와 베타 메뉴에서 **발견 → 진입 → 정상 저장 → 결과 확인 → 다음 대진 재참여**를 측정한다. 게시 전 일일 실행·원천·접수 링크를 확인하고, 실제 접수 후 첫 주의 저장·재참여를 검토한다. 분석 보고서의 실측값은 이번에 확인하지 않았으며 새 광고·외부 게시·메일 자동화는 추가하지 않는다.

되돌리기는 이번 수집기와 workflow 변경을 revert한다. 후보는 `enabled:false`를 유지하고, 운영 원장은 삭제하지 않는다. 조사·실행 근거는 로컬 `.harness/weekly-resume-20261125/`에 보관한다.
