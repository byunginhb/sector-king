# 사용자 참여·경쟁·자랑 및 검색 노출 강화 후보

> 작성일: 2026-11-06
> 추가 요청 반영일: 2026-11-06 — SEO·GEO·AEO·검색 키워드 강화
> 상태: **기획 후보 + 1차 검색·참여 진입 개선 구현·검증. 경쟁 기능 미출시**
> 목적: 다른 에이전트가 같은 후보와 전제를 읽고 제품·UX·데이터·운영 관점에서 검토할 수 있도록 한다.
> 범위: 참여 기능과 검색 노출 강화의 후보, 비교, 우선순위 제안. 확정 설계·구현 계획·배포 지시가 아니다.

## 1. 목표와 제품 방향

사용자 요청은 “참여와 경쟁, 자랑을 위한 장치”다. 다음은 그 요청을 구체화한 제안이며, 효과는 아직 검증되지 않았다.

- **참여:** 시장을 구경하다가 내 선택과 생각을 남긴다.
- **경쟁:** 같은 조건에서 다른 사람과 결과를 비교한다.
- **자랑:** 잘한 선택, 쌓인 기록, 나만의 관점을 보여준다.
- **재방문:** 지난 선택의 결과를 확인하고 다음 라운드에 참여한다.

초기 대상 가설은 한국어로 미국·한국 주식과 섹터 흐름을 살펴보는 개인 투자자다. 초보자는 짧은 선택·퀴즈로, 적극적인 사용자는 예측 기록·분석으로 참여할 수 있게 한다. 실제 이용자 구성과 참여 의향은 별도 확인이 필요하다.

제품 방향 제안은 **“내 시장 관점을 남기고, 결과를 확인하며, 기록으로 인정받는 곳”**이다. 가격 화면과 분리된 출석 게임보다 기존 섹터·종목 분석 경험에 연결한다.

## 4. 후보별 구체화

### E01. 이번 주 섹터 매치

- **경험:** “다음 주, 어느 섹터가 더 강할까요?”라는 동일 문제에 한쪽을 고른다. 예: 반도체 vs 바이오. 실제 대진은 서비스의 섹터 분류와 데이터 커버리지 안에서 선정한다.
- **돌아올 이유:** 마감 후 내 선택, 다른 사람의 선택 분포, 최종 결과를 확인한다.
- **최소 범위:** 시장별 주간 대진 하나, 계정당 선택 하나, 접수·잠금·정산 상태, 결과 기록. 주문·매매 기능은 필요 없다.
- **재사용/추가:** 기존 섹터 화면과 시장 데이터 활용. 라운드·선택·정산 결과 저장과 서버 판정은 신규.
- **핵심 조건:** 같은 시장의 두 섹터를 같은 기간·같은 산식으로 비교한다. 마감 전 수정 가능 여부와 마감 후 잠금 규칙을 공지한다. 투표 분포는 마감 후 공개하는 안을 우선 검토한다.
- **성공 신호:** 첫 참여 전환율, 결과 확인율, 다음 라운드 재참여율.

### E02. 종목·섹터 분위기 투표

- **경험:** 종목 또는 섹터 상세에서 향후 일정 기간의 상승·중립·하락 관점을 남기고 집계 분포를 본다.
- **최소 범위:** 고정된 전망 기간, 기간별 계정당 한 표, 집계 인원·시각 표시. 첫 버전은 적중률을 채점하지 않는다.
- **재사용/추가:** 상세 화면 활용. 투표 저장·중복 방지·집계 API 추가.
- **핵심 조건:** 적은 표본을 시장 전체 여론처럼 표현하지 않는다. 최소 집계 인원 미달은 숫자 대신 “집계 중”으로 표시하고, 참여가 적을 때는 소수 종목에 질문을 모은다.
- **성공 신호:** 투표 완료율과 재투표율. 가격 예측 정확도는 이 기능의 초기 지표가 아니다.

### E03. 타임스탬프 예측 노트 — “내가 이렇게 봤다”

- **경험:** 종목·섹터, 전망 방향, 종료일, 근거를 기록하고 나중에 결과와 함께 복기한다.
- **최소 범위:** 비공개 기본, 서버 기록 시각, 전망 잠금, 결과·회고. 공개는 기록별 명시적 선택.
- **재사용/추가:** 메모 입력 UX는 참고하되 기존 개인 메모와 별도로 불변 예측 버전을 저장한다.
- **핵심 조건:** 공개 성과에는 선택한 성공 사례뿐 아니라 해당 공개 기록 범위의 실패·채점 불가 건수도 보여준다. 삭제·공개 철회가 점수 세탁 수단이 되지 않도록 개인정보 삭제 정책과 집계 정책을 함께 설계한다.
- **성공 신호:** 전망 작성 후 결과 확인·회고 작성 비율.

### E04. 시즌 랭킹·섹터왕 칭호

- **경험:** 주간 매치 결과로 4주 시즌 순위를 보고 “이번 시즌 섹터왕” 같은 기간 한정 칭호를 얻는다.
- **최소 범위:** E01 결과 기반 시장별 보드, 내 순위, 공동 순위, 지난 시즌 기록. 첫 버전에는 상금·환금성 포인트를 넣지 않는다.
- **재사용/추가:** 기존 종목 랭킹의 표시 패턴은 참고 가능. 사용자 순위 집계는 신규이며 종목 점수와 섞지 않는다.
- **핵심 조건:** 산식·최소 참여 횟수를 시작 전에 고정한다. 적중 수와 유효 참여 수를 함께 표시하고, 적은 표본의 우승을 투자 실력 인증으로 표현하지 않는다.
- **성공 신호:** 시즌 중 반복 참여, 다음 시즌 복귀, 순위 확인 후 재참여 비율.

### E05. 업적 배지·컬렉션

- **경험:** “첫 예측”, “결과 복기 3회”, “서로 다른 섹터 탐구”처럼 구체적 행동을 배지로 모은다.
- **최소 범위:** 배지 3~5개, 획득 조건·시각, 대표 배지 하나 선택. 확률형 뽑기·포인트 상점은 제외한다.
- **재사용/추가:** 사용자 데이터와 실제 완료 기록 활용. 서버에서 검증한 획득 이력 추가.
- **핵심 조건:** 클릭 수·새로고침·무의미한 메모 반복을 보상하지 않는다. 접속을 강요하는 연속 출석보다 학습·복기 완료를 우선한다.
- **성공 신호:** 첫 배지 획득 후 다음 의미 있는 행동으로 이어진 비율.

### E06. 공개 투자 관점 프로필

- **경험:** 별도 닉네임, 관심 섹터, 대표 배지, 시즌 기록을 보여주는 개인 페이지를 만든다.
- **최소 범위:** 공개 동의, 공개용 닉네임, 공개 범위 선택, 비공개 전환. 계좌·실명·실제 잔고 인증은 제외한다.
- **재사용/추가:** 기존 로그인 프로필과 분리된 공개 필드·공개 전용 응답이 필요하다.
- **핵심 조건:** 이메일·OAuth 실명·개인 메모·비공개 워치리스트가 공개 응답에 섞이지 않아야 한다. 비공개 전환 시 검색 노출·캐시 처리도 정의한다.
- **성공 신호:** 자발적 공개 설정률, 공개 페이지를 통한 신규 참여 전환.

### E07. 검증 가능한 성과 공유 카드

- **경험:** “이번 시즌 4회 중 3회 적중”처럼 기간·표본 수가 붙은 결과를 이미지와 링크로 공유한다.
- **최소 범위:** 라운드 결과 또는 시즌 기록 카드 하나, 공유 미리보기, 원본 결과 링크. A 단계에서는 전체 공개 프로필 없이 선택한 결과만 공개할 수 있게 한다.
- **재사용/추가:** 기존 링크 공유·이벤트 측정 재사용. 공개 동의와 서버 결과를 읽는 카드 생성·공개 결과 응답은 신규.
- **핵심 조건:** 클라이언트가 보낸 임의 점수로 카드를 만들지 않는다. 예시 수치와 실적을 구분하고, 기간·시장·적중/참여 수·모의 결과 여부를 카드에 담는다. 철회 후에도 이미 내려받은 이미지는 회수할 수 없음을 공개 전에 알린다.
- **성공 신호:** 카드 생성·공유 실행·링크 유입·유입자의 첫 참여를 각각 측정. 공유 버튼 클릭을 유입 성공으로 세지 않는다.

### E08. 친구 초대 1:1 대결

- **경험:** 친구에게 “이번 주 이 매치 같이 하자” 링크를 보내고 라운드 종료 후 나란히 결과를 본다.
- **최소 범위:** E01의 동일 대진을 공유하는 초대 링크, 수락, 양쪽 결과. 독자적인 거래·점수 엔진은 만들지 않는다.
- **핵심 조건:** 선택 전 상대 답을 숨기고 같은 마감을 적용한다. 동의 없는 친구 추가·연락처 수집·자동 메시지 발송은 하지 않는다.
- **성공 신호:** 초대 수락률, 수락자의 첫 참여율, 둘 다 다음 라운드에 참여한 비율.

### E09. 고정 바스켓 모의 리그

- **경험:** 시즌 시작 전에 같은 시장의 종목 3~5개를 골라 고정 비중의 가상 바스켓 성과를 겨룬다.
- **최소 범위:** 시즌 전 구성 잠금, 동일 시작 조건, 일별 평가, 기준 지표 비교. 실시간 주문·자유 매매는 후속 후보로 남긴다.
- **재사용/추가:** 종목 데이터 활용. 구성 스냅샷·가격 이력 품질 확인·평가 엔진·재정산 이력은 신규.
- **핵심 조건:** 분할·배당·상장폐지·거래정지·결측 처리와 기준 통화를 먼저 정해야 한다. 현재 관심 종목 평균 등락률을 수익률로 대체할 수 없다.
- **성공 신호:** 시즌 완료율과 다음 시즌 참가율. 데이터·정산 비용이 크므로 E01 참여 수요 확인 후 검토한다.

### E10. 시장 읽기 퀴즈·주간 미션

- **경험:** “시총 증가액이 실제 자금 유입과 같은가?” 같은 기존 가이드 기반 문제를 풀고 해설을 본다. “서로 다른 섹터 두 곳을 비교하고 차이를 기록하기” 같은 탐구 미션도 가능하다.
- **최소 범위:** 검수된 고정 문제 묶음, 해설, 개인 완료 기록. 배지가 필요하면 E05와 연결한다.
- **핵심 조건:** 시점에 따라 답이 바뀌는 문제는 기준일을 고정한다. 정답 조회 후 재시도는 학습으로 허용하되 최초 시도 경쟁 기록과 구분한다.
- **성공 신호:** 완료 후 관련 데이터 화면·가이드로 이동한 비율과 다음 주 재참여.

### E11. 근거 한 줄·주간 분석 선정

- **경험:** 예측 근거를 짧게 공개하고, 운영자가 근거·명확성·복기 품질을 기준으로 “이번 주 분석”을 선정한다.
- **최소 범위:** 글자 수 제한, 명시적 공개, 신고·숨김, 선정 기준. 초기에는 댓글·DM·실시간 채팅을 열지 않는다.
- **핵심 조건:** 좋아요 수만으로 우승자를 정하지 않는다. 사칭·광고·도배·특정 종목 선동에 대한 신고 처리와 운영 담당자가 먼저 필요하다.
- **성공 신호:** 읽힌 분석의 비율, 근거 있는 작성의 반복, 신고 처리 시간. 글 수만으로 성공을 판단하지 않는다.

### E12. 섹터 팀전·클럽

- **경험:** 관심 섹터 팀에 소속되어 시즌 참여 기록과 공동 미션을 쌓고 팀 결과를 자랑한다.
- **최소 범위:** 팀 선택, 시즌 중 이동 제한, 팀 참여 현황과 명확한 집계 규칙. 채팅과 클럽장 권한은 후속 검토한다.
- **핵심 조건:** 큰 팀이 인원만으로 이기지 않도록 최소 참여 인원·유효 참여자 기준을 정해야 한다. 소수 사용자 단계에서는 팀을 잘게 나누지 않는다.
- **성공 신호:** 팀 가입 후 반복 참여 증가와 팀별 참여 편중. 활동 사용자가 충분한지 확인한 뒤 검토한다.

## 5. 먼저 실험할 조합 제안

### 조합 A — 섹터 매치 → 시즌 기록 → 공유 카드 (우선 제안)

**E01 + E04 + E07**을 하나의 흐름으로 연결한다. 핵심 선택 행동 하나를 결과 확인·경쟁·자랑에 공통으로 쓰기 때문에 제품 정체성과 가깝다.

```text
섹터 화면에서 주간 매치 발견
  → 로그인 후 한쪽 선택
  → 마감 시 선택 잠금
  → 데이터 확정 후 결과·내 시즌 기록 확인
  → 원하면 공개 닉네임과 해당 결과만 공유
  → 친구가 결과 링크로 들어와 다음 라운드 참여
```

최소 공개 닉네임·동의는 공통 기반에 포함하되, E06의 전체 프로필·E08의 대결 기능까지 첫 범위에 넣지 않는다. 초기 참여자가 적으면 빈 순위표 대신 내 결과와 전체 참여 수를 먼저 보여준다. 참가자를 꾸며 넣지 않는다.

### 조합 B — 퀴즈·미션 → 배지 → 학습 기록

**E10 + E05**, 이후 필요하면 E06을 붙인다. 입문자의 참여 부담이 낮고 예측 승패에 관심 없는 사용자도 포용한다. 대신 문제·해설을 꾸준히 검수할 담당자가 필요하다.

### 조합 C — 예측 노트 → 공개 분석 → 관점 프로필

**E03 + E11 + E06**으로 적극적인 분석 사용자를 모은다. 깊이 있는 기록과 인정에 적합하지만 글쓰기 부담과 공개 콘텐츠 운영 부담이 커서 첫 실험으로는 범위가 넓다.

위 세 조합은 선택을 돕는 제안이다. 사용자가 어느 조합을 채택했다고 간주하지 않는다.

## 6. 경쟁 기능을 선택하면 먼저 확정할 계약

다음은 구현 전에 합의할 항목이다. 괄호 안은 초기 제안이며 확정 사항이 아니다.

| 항목 | 초기 제안 / 확인할 점 |
| --- | --- |
| 라운드 범위 | 한국과 미국 보드를 분리. `global` 식별자는 기존처럼 미국을 의미. 같은 대진·동일 기회끼리 경쟁 |
| 접수·평가 시점 | 주 시작 기준 종가가 확정된 뒤, 다음 거래 세션 시작 전에 접수 마감. 그 기준 종가부터 주 종료 종가까지 평가. 구체 시각은 거래소 시간·휴장·DST를 반영해 고정 |
| 섹터 성과 | 시작 시 구성 종목을 고정한 동일 비중 가격 변동률 평균을 후보로 검토. 기존 시총 변화 지표와 의미가 다르므로 별도 정의·명칭 필요 |
| 데이터 결측·기업행동 | 임의의 최신가로 확정하지 않음. 정산 보류·무효 조건, 가격 조정 기준, 수정 데이터 재정산 정책을 먼저 정함 |
| 점수 | E01 유효 라운드 적중 1점·실패 0점 제안. 비교값은 사전 정의한 정밀도로 판정하고 동률·무효는 양쪽 모두 유효 참여 분모에서 제외 |
| 시즌 자격·동점 | 4주 시즌·최소 유효 참여 2회 제안. 동일 점수는 공동 순위, 적중 수/유효 참여 수 병기. 빠른 클릭·임의 추첨으로 순위를 가르지 않음 |
| 공정성 | 서버 시각·마감 잠금·중복 참여 제한·검증된 정산 결과가 기준. 새 계정으로 무한 도전하는 악용 가능성과 대응 수준을 별도 평가 |
| 공개 범위 | 기본 비공개, 공개 보드·카드 참여는 명시적 동의. 공개 닉네임과 공개 전용 DTO 사용. 본인 행 RLS를 전체 공개로 넓히지 않음 |
| 보상 | 초기에는 기록·칭호만. 참여권 구매, 현금성 보상, 유료 회원 가산점은 범위 밖 |
| 정정·중단 | 결과·순위·배지·공유 링크가 같은 정산 버전을 참조. 데이터 장애 시 접수/정산/공개를 각각 멈출 수 있어야 함 |

현재 DB의 가격성 필드는 네이티브 통화다. 가격 API 응답은 `toUsd(value, ticker)` 계약을 유지하고 혼합 통화의 금액 집계는 USD 정규화 후 수행한다. 같은 티커의 비율 계산은 통화 변환이 필수는 아니지만, 과거 수익률에 현재 환율을 임의 적용하거나 표시 통화 토글로 경기 점수가 달라지면 안 된다. 스냅샷의 조정주가·배당 처리 여부는 이번 조사에서 검증하지 않았다.

신규 참여 데이터는 기존 Supabase 사용자 저장소 경계를 우선 검토한다. 경쟁 결과는 서버에서 확정하며 클라이언트 이벤트나 사용자 삽입 가능한 활동 로그로 점수를 인정하지 않는다. 후보 검토만을 위해 새 DB·인증·저장소 서비스를 만들 필요는 없다.

## 7. 효과를 확인할 최소 실험

**가설:** 자신의 선택이 남고, 결과와 순위를 확인할 수 있으면 단순 열람보다 다음 라운드에 다시 참여할 이유가 생긴다. 현재 기준선·트래픽·달성 목표는 확인되지 않았으며 수치를 성과 보장처럼 제시하지 않는다.

| 단계 | 지표와 분모 | 측정 시 주의 |
| --- | --- | --- |
| 발견 → 참여 | 첫 제출 완료 사용자 / 참여 가능한 기능 노출 사용자 | 비로그인과 로그인 사용자를 구분, 서버 저장 성공을 완료로 판단 |
| 참여 → 결과 확인 | 정산 후 결과를 본 참가자 / 정산된 참가자 | 아직 정산되지 않은 라운드는 분모 제외 |
| 반복 참여 | 다음 라운드에 다시 제출한 참가자 / 다음 라운드 참여 기회가 있었던 이전 참가자 | 라운드 간격과 측정창 고정 |
| 경쟁의 추가 효과 | 순위 기능 노출 집단과 비교 집단의 재참여율 차이 | 표본이 충분할 때만 비교 실험. 자발적으로 순위표를 연 사람의 높은 재참여만으로 인과를 주장하지 않음 |
| 자랑 → 유입 | 카드 생성, 공유 실행, 공개 링크 유입을 각각 집계 | 복사·공유창 열기와 실제 게시를 구분 |
| 유입 → 활성화 | 공유 링크 유입자 중 첫 참여 완료자 / 공유 링크 유입자 | 개인 이메일·닉네임을 분석 이벤트나 UTM에 넣지 않음 |
| 품질 | 무효·재정산 비율, 신고, 개인정보 공개 관련 문의 | 참여 수가 늘어도 공정성·신뢰 문제가 커지면 확장 보류 |

출시 전 유효 이벤트·집계 기간·비교 기준을 고정하고, 가능하면 도입 전 기준선 또는 미노출 비교 집단을 확보한다. 주간 기능은 최소 한 시즌의 결과를 관찰하되 소표본이면 방향성만 기록한다. 사전 합의한 재참여 목표에 못 미치면 후보를 늘리기 전에 발견 동선·참여 부담·결과 가치 중 어디서 이탈하는지 확인한다.

운영안은 일일 접수 마감·데이터 신선도·정산 지연·공유 링크 점검, 주간 재참여·유입 전환 검토다. 실제 일정 자동화나 외부 게시를 활성화하는 문서는 아니다. 첫 실험의 유입 경로는 기존 화면과 사용자 자발적 공유로 한정하며, 이메일·푸시·SNS 자동 발행은 별도 범위로 둔다.

## 8. 후속 에이전트 검토 가이드

다음 역할은 검토 관점 제안이다. 이번 문서 작성에서 해당 에이전트를 실행한 것은 아니다.

| 관점 | 답해야 할 질문 | 산출물 제안 |
| --- | --- | --- |
| 제품·리텐션 | 어떤 사용자 욕구가 가장 강한가? A/B/C 중 첫 실험은 무엇인가? | 후보 ID를 인용한 채택·보류 의견과 실험 목표 |
| UX·디자인 | 기존 어느 화면에서 발견·참여·복기하는가? 빈 상태와 비공개 기본값은 어떻게 보여주는가? | 선택된 조합의 최소 사용자 흐름 |
| 데이터·정산 | 고정 구성 종목·가격 시점·기업행동 처리가 가능한가? 정산 결과를 재현할 수 있는가? | 데이터 가용성·채점 계약·장애 처리안 |
| 인증·보안 | 공개 결과와 개인 데이터는 어떻게 분리하는가? 마감·중복·점수 위조는 어떻게 막는가? | 공개 응답 경계·권한·악용 방지 검토 |
| 운영·성장 | 누가 대진·문제·신고·정정을 관리하는가? 공유가 실제 참여로 이어지는가? | 주간 운영 부담과 측정 계획 |

검토 의견에는 **후보 ID, 장점, 주요 위험, 최소 범위, 선행 의존성, 추천/보류 이유**를 남긴다. 아이디어를 구현 승인으로 해석하거나 기존 종목 랭킹·개인 메모·관심 종목 변동률의 의미를 바꾸지 않는다. 구현을 선택하면 프로젝트 오케스트레이터 절차에 따라 별도 설계를 진행한다.

## 10. 이번 문서의 검증 범위

기존 소스·과거 기획과의 연결 및 문서 링크를 확인했다. 신규 제품 코드는 작성하지 않았다. 운영 DB·실제 배포·이용자 지표·수익률 데이터 품질·시장 수요·법률 검토는 수행하지 않았으며, 후보의 효과·규모 평가는 검증 전 가설이다.

추가된 검색 노출 제안은 로컬 SEO 관련 소스와 공식 웹 문서를 함께 확인했다. 실제 검색 순위·색인·크롤러 접근·Search Console 권한·키워드 검색량은 확인하지 않았다.

## 11. SEO·GEO·AEO·검색 키워드 강화

### 11.1 목표와 용어

사용자의 추가 목표는 **관련 검색에서 가능한 한 넓게 발견되고, 검색·AI 답변을 통해 실제 사용자가 유입되도록 하는 것**이다. 노출 이후 데이터 탐색 → 가입 → 첫 참여 → 재참여까지 이어지는 흐름을 함께 설계한다.

| 영역 | 이 문서에서의 의미 | 목표 결과 |
| --- | --- | --- |
| SEO | Google·Naver·Bing 등의 검색에서 공개 페이지를 발견·이해·색인할 수 있게 개선 | 관련 비브랜드 검색의 노출·클릭 확대 |
| AEO | 질문에 대한 직접적이고 근거 있는 답을 제공하도록 콘텐츠 구성 | 검색·답변 서비스가 페이지의 답과 출처를 이해하기 쉬워짐 |
| GEO | 생성형 검색에서 원본 정보·분석·브랜드가 출처 후보로 이해되도록 개선 | AI 답변의 출처 링크·언급 및 관련 유입 확대 |
| 검색 키워드 | 사용자의 표현과 검색 의도를 묶어 적합한 페이지에 연결 | 종목·섹터·지표·학습·참여 의도까지 커버리지 확장 |

Google은 생성형 검색 최적화에도 SEO 기본기를 적용하며, `llms.txt`·AI 전용 마크업·모든 질의 변형별 페이지가 필수라는 주장을 부정한다. 이 문서도 이를 기준으로 삼는다. 노출·상위 순위·AI 인용은 보장할 수 없다. [Google 생성형 AI 검색 최적화 가이드](https://developers.google.com/search/docs/fundamentals/ai-optimization-guide)

### 11.2 기존 구현을 확인한 뒤 보강할 것

기존 [`SEO·AEO·GEO 개발 프롬프트`](../../../sector-king-seo-aeo-geo-development-prompt.md)는 참고 자료다. 그 문서의 과거 결함 목록이나 구현 지시를 이번 요청의 현재 결함·구현 승인으로 해석하지 않는다.

| 로컬에서 확인한 기반 | 이번 기획에서의 후속 확인 |
| --- | --- |
| [`app/robots.ts`](../../../../app/robots.ts)에 공개 경로 허용, 검색·학습 크롤러 그룹 구분이 있음 | 운영 응답·WAF·렌더링 필수 자산 접근을 확인. robots 설정만으로 실제 수집 성공을 선언하지 않음 |
| [`app/sitemap.ts`](../../../../app/sitemap.ts)에 종목·산업·섹터·뉴스·가이드와 수정일 처리 존재 | 실제 URL의 200 응답·canonical·색인 허용 여부·정확한 변경일 및 누락 여부를 대조 |
| 종목·섹터 페이지에 개별 canonical과 서버 데이터 표현이 있음 | 대표 유형별 초기 HTML과 렌더 후 본문을 비교. 다른 페이지 유형도 같은 상태라고 추정하지 않음 |
| [`SeoSummary`](../../../../components/seo/seo-summary.tsx), [`StockSeoFacts`](../../../../components/seo/stock-seo-facts.tsx) 존재 | 로딩 대체 요약이 최종 본문에도 일관되게 전달되는지, 질문·표·기준일·내부 링크가 실제로 읽히는지 확인 |
| [`components/json-ld.tsx`](../../../../components/json-ld.tsx)에 여러 구조화 데이터 컴포넌트 존재 | 페이지 유형·본문·공식 지원 범위와 대조. JSON-LD만 있고 실제 답변이 화면에 없는 구성은 피함 |
| [`lib/seo-faq.ts`](../../../../lib/seo-faq.ts)에 질문·답변 데이터가 있음 | 현재 산식·유료 접근 범위·데이터 갱신 주기와 답변이 맞는지 검토 |
| 가이드·데이터 출처·편집 정책 페이지와 GA 이벤트 기반 존재 | 페이지가 있다는 사실과 신뢰도·검색 성과·실제 데이터 수집 여부를 구분 |

특히 기존 코드 주석의 “FAQ 리치결과·AI 직접 인용” 기대는 수정 검토 대상이다. Google 공식 변경 이력상 FAQ 리치결과는 **2026-05-07부터 종료**되었으므로 이를 노출 확대의 성과 목표로 삼지 않는다. FAQ 본문은 사용자 질문에 답하는 용도로 유지·보강할 수 있다. [Google 공식 변경 이력](https://developers.google.com/search/updates#may-2026)

### 11.3 검색 노출 강화 후보

여기서 **P0**는 기존 페이지의 발견·측정 기반 점검, **P1**은 검색 의도와 답변 콘텐츠 강화, **P2**는 참여 기능 출시·데이터 축적 이후 확장을 뜻한다. 현재 결함 판정이나 일정 확정이 아니다.

| ID | 후보 / 우선순위 | 최소 범위 | 완료를 판단할 근거 |
| --- | --- | --- | --- |
| S01 | 크롤링·색인·초기 HTML 점검 / P0 | 대표 페이지의 응답·robots·noindex·canonical·sitemap·모바일 렌더·WAF를 대조. 비공개 경로는 인증 유지 | 실제 배포 URL 응답과 검색 도구 검사 기록. 로컬 코드 존재만으로 통과 처리하지 않음 |
| S02 | 검색 의도별 대표 페이지 강화 / P1 | K01~K12 중 기존 페이지에 맞는 묶음부터 매핑. 한 의도에 대표 URL 하나, 고유 제목·H1·요약·관련 링크 | 키워드→대표 URL 표와 실제 본문의 일치, 동일 의도 중복 페이지 정리 |
| S03 | 섹터·종목별 고유 데이터 설명 / P1 | 기존 상세 페이지에 실제 구성 종목·시장·기준일·변화 기여·분류 근거를 설명 | 이름만 바꾼 템플릿을 넘어 해당 대상에만 해당하는 표·설명·근거 제공 |
| S04 | 질문형 답변·지표 용어 해설 / P1 | 기존 가이드를 우선 보강하고 질문→직접 답→근거→데이터 화면 링크 제공 | 답변과 지표 정의·산식·화면이 일치, 초기 HTML과 최종 화면에서 접근 가능 |

| S06 | 참여 결과·시즌 아카이브 / P2 | E01/E04 출시 후 검수된 공개 라운드·시즌 결과를 안정적인 URL에 축적 | 익명 집계·대진·기간·판정 근거가 있는 결과 본문. E07 개인 공유 링크와 색인 정책 분리 |
| S07 | 신뢰·브랜드·이미지 검색 보강 / P1 | 섹터킹/Sector King 표기, 작성·검토 책임, 출처·방법론·갱신 주기 정합성. 실제 차트 이미지에 설명·대체 텍스트·본문 연결 | 사용자가 근거를 확인할 수 있고 이미지와 본문 수치가 일치. 외부 소개는 실제 제품을 확인한 자료만 준비 |

사이트 중복 URL과 대표 주소 정리는 Naver에도 필요한 기본 항목이다. [Naver 웹사이트 제작 가이드](https://searchadvisor.naver.com/guide/seo-basic-create)

검색용 봇과 학습용 봇 허용은 별도 정책이다. 예를 들어 OpenAI는 `OAI-SearchBot`과 `GPTBot` 설정을 독립적으로 설명한다. 기존 학습 허용 정책을 노출 확대 명목으로 임의 변경하지 않고, 검색 접근의 실제 동작부터 확인한다. [OpenAI 크롤러 안내](https://developers.openai.com/api/docs/bots)

Google AI 검색은 Search Console의 **Search generative AI** 포함 설정도 확인한다. 문서상 기본값이 포함이어도 실제 속성·상위 속성의 상속 상태는 별도 확인해야 한다. 이번에는 설정을 열거나 변경하지 않았다. [Google AI 검색 제어 안내](https://support.google.com/webmasters/answer/16908024)

초기 검증 순서는 **제품과의 적합성·기존 페이지의 답변 완성도·현재 노출 증거**를 기준으로 정한다. K01/K04/K05/K06처럼 서비스의 차별점과 직접 연결되는 묶음부터 검토하고, 실제 데이터가 충분한 K02/K03으로 넓히는 안을 제안한다. 일반적인 “주식”, “주가 전망” 같은 큰 단어의 검색량만으로 우선순위를 정하지 않는다.

실행 시 키워드별로 `의도 묶음 / 대표 URL / 기존 노출·클릭 / 현재 답변의 부족한 점 / 보강 내용 / 변경일 / 검토일`을 기록한다. Search Console·Naver 데이터와 검색 결과 관찰로 표현과 우선순위를 수정하며, 없는 검색량 수치나 경쟁도는 만들지 않는다. 맞춤법·동의어·질문 변형은 같은 페이지에서 자연스럽게 다루고 `meta keywords` 태그나 반복 삽입을 주력 작업으로 삼지 않는다.

### 11.5 AEO·GEO용 질문과 답변 구성 후보

초기에는 아래 질문 중 실제 데이터와 방법론으로 답할 수 있는 항목을 기존 대표 페이지에 보강한다.

1. 한국·미국 주식을 섹터별로 볼 수 있는 곳은 어디인가?
2. 이번 주 강한 섹터는 어떤 기준으로 비교하는가?
3. 반도체 섹터에 어떤 종목이 포함되고, 왜 그렇게 분류되는가?
4. 섹터의 시가총액이 늘면 실제 돈이 그만큼 들어온 것인가?
5. 섹터 로테이션과 개별 종목 상승은 어떻게 다른가?
6. 섹터킹의 단기·장기 점수는 무엇을 나타내는가?
7. 목표주가 적중률과 투자 수익률은 같은 지표인가?
8. 섹터 매치의 결과·순위·동점은 어떻게 결정되는가? — E01/E04 출시 후에만 제공.

페이지 구성 제안은 `질문/주제 → 짧고 직접적인 답 → 기준일이 있는 실제 표·사례 → 계산·해석·한계 → 원본/방법론 링크 → 관련 탐색·참여 행동`이다. 특정 문장 수·글자 수·문단 분할을 검색 순위 규칙으로 취급하지 않는다.

금융 데이터의 현재 관찰, 과거 결과, 미래 전망, 사용자 의견을 명확히 구분한다. 기준 시각·시간대·통화·대상 시장·표본 수를 밝히고, 과거 분석의 오류를 날짜만 바꿔 덮지 않는다. 직접 산출한 섹터 비교·변화 기여·실제 정산 결과처럼 서비스 고유 근거를 우선한다. 이 구성은 작성자의 콘텐츠 제안이며 AI가 이를 반드시 인용한다는 뜻은 아니다.

### 11.6 참여 기능과 검색 유입의 연결

```text
섹터·종목·시장 해석 검색 / AI 답변의 출처 링크
  → 공개 데이터·해설 페이지에서 질문 해결
  → 관련 주간 매치 또는 학습 미션 발견
  → 로그인 후 첫 참여
  → 결과 확인·복기·시즌 기록
  → 동의한 결과 공유
  → 새 사용자의 탐색·참여
```

E01/E04의 공개 결과는 일회성 이벤트를 설명 가능한 기록으로 축적할 기회다. 다만 **공유 가능한 URL과 검색 색인을 허용할 URL은 별도로 결정**한다.

- **색인 우선 후보:** 완성된 섹터·종목 설명, 검수된 가이드·주간 분석, 충분한 정보가 있는 공식 라운드·시즌 결과.
- **기본 색인 제외 후보:** 개인 공유 카드·초대 링크·빈 공개 프로필·임시 투표·검색/정렬/필터 조합. 프로필은 별도 공개·색인 정책 합의 후 재검토한다.
- **비공개 유지:** `/me`와 개인 메모·비공개 기록·인증 정보. robots 차단은 접근 제어가 아니며 인증·권한 검사를 유지한다.
- **공개 콘텐츠의 제외 처리:** 공개 URL을 `noindex`로 제외할 때는 크롤러가 해당 지시를 읽을 수 있게 한다. robots 차단과 `noindex`를 무조건 함께 적용하면 제외 지시가 읽히지 않을 수 있다.

중복·빈 페이지와 키워드만 다른 URL을 대량 생성하지 않는다. 사용자 가치 없이 검색 조작을 목적으로 확장하는 콘텐츠는 Google 스팸 정책의 대상이 될 수 있다. [Google 확장형 콘텐츠 악용 정책](https://developers.google.com/search/docs/essentials/spam-policies#scaled-content)

### 11.7 실행 순서와 측정 기준

1. **기반·기준선:** S01/S08부터 확인한다. 도구 소유권·접근 권한, 대표 URL별 초기 HTML·색인 상태·노출·클릭을 기록한다.
2. **기존 페이지 개선:** 키워드 묶음과 대표 URL을 연결하고 S02~S04/S07을 적용할 대상을 선택한다. 새 URL보다 기존 페이지의 미해결 질문 보강을 우선한다.
3. **고유 콘텐츠 축적:** 데이터와 검수 역량이 있는 범위에서 S05를 운영한다. 최초 후보는 핵심 질문 10~20개 이내이며, 발행량 목표가 아닌 검토 대상 수다.
4. **참여 기능과 확장:** 실제 E01/E04 출시 후 S06을 검토한다. 기능이 없을 때 예측 대회·모의 리그가 제공되는 것처럼 홍보하지 않는다.
5. **반복 개선:** 일일 오류·데이터 신선도·공개 링크 점검, 주간 질의·페이지·참여 전환 검토. 색인 지연·계절성·시장 이슈를 고려해 변경 전후를 비교하고, 근거 없이 페이지 수를 늘리지 않는다.

| 성과 단계 | 확인할 지표 | 해석의 한계 |

현재 Google 공식 문서에는 별도 생성형 AI 노출 보고서가 안내되어 있다. 실제 계정에서의 데이터 제공 여부를 확인하며, 모든 AI 노출·클릭을 이 보고서 하나로 측정할 수 있다고 간주하지 않는다. [Google 생성형 AI 성과 보고서](https://support.google.com/webmasters/answer/16984139)

후속 SEO 담당 에이전트는 **S 후보 ID와 K 키워드 묶음, 대표 URL, 현재 상태의 증거, 최소 수정 범위, 검증 방법**을 묶어 검토한다. UX·콘텐츠 담당은 검색 질문이 페이지에서 해결되는지, 데이터 담당은 수치·정의·갱신일이 맞는지, QA 담당은 운영 URL과 실제 측정 결과를 독립 확인한다. 이번 문서만으로 계정 설정 변경·새 콘텐츠 발행·외부 자동 게시를 시작하지 않는다.

공식 문서 확인일은 2026-11-06이다. 실제 구현 시 지원 기능·크롤러 정책·도구 제공 범위를 다시 확인한다.

## 12. 지금 착수할 작업의 우선순위 — 2026-11-07

### 12.1 판단 근거와 현재 범위

이번 요청은 실행 가능한 작업의 순서 정리다. 아래의 “즉시 가능”은 현재 구조로 조사·설계 또는 구현에 착수할 수 있다는 의미이며, 구현·테스트·배포 완료를 뜻하지 않는다. 우선순위는 기대 효과, 기존 기반 재사용, 선행 의존성, 운영 부담을 종합한 작성자의 판단이다. 실제 검색량·전환 성과를 근거로 한 확정 순위는 아니다.

추가 코드 확인에서 다음 기반을 확인했다.

- robots·sitemap·종목 및 섹터 canonical·서버 요약은 이미 있고, [`SEO 회귀 테스트`](../../../../__tests__/unit/seo.test.ts)도 있다. 이를 처음부터 재구축하는 작업은 우선 범위에서 제외한다.
- 종목 페이지 제목은 이미 “주가·시가총액·섹터 순위”를 포함한다. 제목에 키워드를 처음 추가하는 작업으로 중복 계획하지 않는다.
- 랭킹 화면은 점수 설명을 이미 제공한다. [`FAQ 데이터`](../../../../lib/seo-faq.ts), [`랭킹 초기 HTML`](../../../../app/rankings/page.tsx), 최종 화면·실제 산식·접근 정책의 설명이 일치하는지부터 대조한다. 이번 확인만으로 불일치가 확정된 것은 아니다.
- [`워치리스트 훅`](../../../../hooks/me/use-watchlist.ts)에 `add_to_wishlist`, [`공유 훅`](../../../../hooks/use-share.ts)에 `share` 이벤트가 있다. 기존 이벤트의 중복 발송 없이 누락된 흐름만 보강한다. 실제 GA 수집 여부는 미확인이다.
- 주간 라운드·시즌·업적 등의 신규 경쟁 기능은 별도 데이터 계약이 필요하다. 개인 메모·관심 종목 평균 변동률로 결과 원장을 대신하지 않는다.

### 12.3 첫 실행 묶음 제안

첫 작업은 **1~3번을 기존 공개 페이지 중심의 작은 묶음으로 진행**하는 안을 추천한다. 신규 DB 없이 검색 진입점과 이미 제공하는 사용자 가치를 연결할 수 있다. 다음 항목은 착수 범위를 좁히기 위한 초안이다.

1. **대표 페이지 6종 점검:** 홈, 섹터 목록, 실제 섹터 상세 1개, 실제 종목 상세 1개, 랭킹, 가이드 1개. 표본 점검 결과를 전 사이트 통과로 확대 해석하지 않는다.
2. **기존 가이드 3편 검토:** `/guide/how-to-read-money-flow`, `/guide/market-cap-change-vs-net-buying`, `/guide/sector-rotation`. 이미 답하고 있는 내용은 유지하고 부족한 사례·정의·탐색 연결만 보강한다.
3. **본문과 설명 정합성:** 랭킹의 FAQ·초기 요약·화면 설명과 실제 산식, 무료·유료 접근 문구를 대조하고 확인된 차이만 수정한다.
4. **전환과 측정:** 위 페이지에서 기존 종목·섹터 탐색과 관심 등록으로 이어지는 흐름을 확인한다. 미출시 매치·배지 CTA는 노출하지 않는다.
5. **검증:** 변경에 맞는 기존 테스트·타입 검사·production build, 실제 렌더·공개 URL 확인을 수행한다. 검색 도구 권한이 없으면 미확인으로 남기고 독립적인 콘텐츠·코드 검증은 계속한다.

4번 E01은 그다음 제품 기능의 우선 후보이며, 규칙 설계는 첫 실행 묶음과 독립적으로 진행할 수 있다. 경쟁 기능 전체를 한꺼번에 만들거나 검색 성과가 나타날 때까지 설계를 기다릴 필요는 없다.

이 순서는 검색과 생성형 검색에 공통으로 유용한 기존 페이지·고유 정보의 품질을 먼저 높이는 방향이다. [Google 생성형 AI 검색 최적화 가이드](https://developers.google.com/search/docs/fundamentals/ai-optimization-guide)를 2026-11-07에 재확인했다. 실제 운영 사이트·검색 도구·분석 수집·정산 데이터 검증과 제품 코드 변경은 이번 우선순위 정리에서 수행하지 않았다.

### 12.4 후속 구현 상태 — 주간 매치

2026-11-07 승인 후 E01의 국내 단일 대진을 구현했다. `/weekly-match`, 본인 선택·마감 잠금, 비공개 원장·정산 버전, 일봉 수집과 격리 DB 검사를 추가했다. 은행 7개·조선 5개 모두 11/6 원천 일봉 수집을 확인했다. 상세 규칙·실행·중지 방법은 [주간 매치 운영](weekly-match-operations.md)을 따른다.

**운영 접수는 미활성이다.** 연결된 Supabase 프로젝트가 조회되지 않아 운영 migration과 실제 OAuth 선택 저장을 확인하지 못했다. 기존 섹터 화면의 진입 링크는 `WEEKLY_MATCH_ENABLED` 기본 false로 숨기며, 페이지는 noindex다. 첫 달력 확인·운영 DB 적용·실제 접수 저장·종료 정산 실행 일정을 확보한 뒤 활성화한다. 시즌 순위·공유·자동 대진 생성은 아직 제공하지 않는다.

### 12.5 운영 연결 후속 — 2026-11-09

Supabase 연결을 복구해 기존 `sector-king` 운영 DB에 주간 매치 스키마를 적용했다. 공개 API의 빈 대진 응답, 운영 DB RLS·본인 기록·마감 제한과 익명 접근 차단을 확인했다. 11월 9일 접수 마감은 지나 다음 유효 대진을 `kr-2026-11-16` 한 주로 고정했고, 기준 원본 선저장·일일 실행·정산 재확인 작업을 준비했다. 현재 기준과 중지 방법은 [운영 DB·자동 실행](weekly-match-live-operations.md), 실행 근거는 [후속 검증 기록](weekly-match-live-release-2026-11-09.md)을 따른다.

실제 OAuth 접수와 미래 날짜의 최초 게시·정산은 아직 검증하지 못했으며, 사용자 진입 링크와 검색 노출은 계속 대기한다. 이전 12.4의 “프로젝트가 조회되지 않음” 장애는 해결됐다. 시즌 순위·결과 공유는 검증된 실제 결과가 쌓인 뒤 진행한다.

후속 원격 확인: 단일 라운드 Actions가 실제 첫 실행에 성공했고 `waiting-base` artifact를 보존했다. 운영 배포와 비로그인 데스크톱·모바일 화면/API 검사도 통과했다. 최초 기준 종가 수집 예정은 2026-11-13 18:10 KST이며, 실제 OAuth 접수와 미래 게시·정산은 계속 별도 확인 대상이다.
