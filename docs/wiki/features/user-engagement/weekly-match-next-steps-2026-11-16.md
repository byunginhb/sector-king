# 주간 매치 — 최초 게시 확인과 다음 대진 준비

기준일: 2026-11-16 UTC. 상태: 현재 대진 게시 확인·접수 마감·정산 대기. 다음 대진은 비활성 후보이며 공개 전 검증이 남아 있다.

## 확인된 운영 상태

- `kr-2026-11-16`의 은행 7종목·조선 5종목이 운영 DB와 공개 API에 일치한다. 기준일은 11/13, 종료일은 11/20이다.
- [최초 게시 실행](https://github.com/byunginhb/sector-king/actions/runs/43469997336)의 계획은 `publish`, 영수증은 `success:true`다. 실제 개시는 **11/14 02:09:54 한국시간**이었다. 예정 실행 시각과 실제 게시 시각을 구분한다.
- 위 실행의 보존된 기준 원본과 공개 대진을 대조했고, 12종목 모두 원천 일봉의 기준 종가·거래량과 일치했다. 공개 API에는 원본 가격·감사 자료·사용자 신원을 넣지 않는다.
- 접수는 **11/16 09:00 한국시간**에 마감됐다. DB 정산은 아직 0건이며 [11/15 실행](https://github.com/byunginhb/sector-king/actions/runs/43734731163)의 계획은 `waiting-end`다. workflow는 활성 상태다.
- 실제 비로그인 본인 기록 조회·저장 요청은 모두 HTTP 401과 `private, no-store`를 반환했다. 취소·코드 누락 콜백은 같은 서비스의 로그인 화면으로 돌아갔다. 세 테이블의 RLS가 활성 상태다.

이번 확인은 기준가격·게시·인증 경계 검사다. 실제 Google OAuth 로그인, 로그인 후 개인 기록 조회, 실제 선택 저장·변경 성공을 뜻하지 않는다.

## 1. 지금 진행할 부분과 사용자 개입

이 대화의 브라우저 도구가 `Browsers: Error: The browser access host is unavailable`을 반환해 실제 OAuth 검증을 진행하지 못했다. Chrome은 실행 중으로 관찰됐지만 연결된 브라우저 목록은 비어 있었다. 브라우저 연결 활성화를 요청했으며, 연결되면 다음 순서로 확인한다.

1. `https://sector-king.com/login?redirect=%2Fweekly-match`에서 기존 Google 로그인으로 시작한다. 계정 선택·비밀번호·2단계 인증은 필요한 경우 사용자가 직접 처리한다. 비밀값이나 세션을 채팅으로 받지 않는다.
2. 로그인 후 `/weekly-match` 복귀와 본인 기록 조회를 확인한다. 현재 대진의 선택 UI는 마감 상태를 유지해야 한다. 로그인만으로 저장 검증을 완료 처리하지 않는다.
3. 다음 정상 대진이 실제 기준가격으로 게시되고 접수 중일 때 직접 링크로 본인 선택 저장 → 새로고침 후 유지 → 반대편으로 변경 → 재조회 일치를 확인한다. 이는 정상 참여 기록으로 남는다. 현재 마감을 늘리거나 운영 DB에 검증용 라운드·가짜 선택을 만들지 않는다.
4. 정상 저장 검증까지 통과한 뒤 기존 섹터 화면의 참여 링크 공개를 판단한다. 검색 noindex·sitemap 제외는 유지하고, 검색 공개는 결과·본문 검증 후 별도로 판단한다.

추가 가입·설문·동의 절차를 제품에 만들지 않는다. 사용자의 직접 조작이 필요한 범위는 브라우저 연결과 실제 Google 인증이며, 운영·달력·가격 검사는 개발 담당이 수행한다.

## 2. 11/20 이후 현재 대진 정산

**11/20 18:00 한국시간 이후** 실제 자동 실행을 확인한다. GitHub 예약 실행은 지연될 수 있으며, 18:10 정각 완료를 보장하지 않는다.

- 보존된 기준 원본을 복원했는지, 종료 가격 12개가 모두 같은 종료일의 정규장 종가인지, 양쪽 수익률·결과가 원본과 일치하는지 대조한다.
- 결측·기업행사·기준가격 변경이 있으면 `pending`과 원본 증거를 유지한다. 종목을 빼거나 비중을 재분배하지 않는다.
- `pending`이면 현재 설정과 일일 재확인을 유지한다. **11/27 18:00 한국시간 이후**에도 미확인이면 기존 규칙의 자동 무효 처리를 확인한다. 확정 결과를 자동 재계산으로 덮어쓰지 않는다.
- 실행 성공과 실제 정산 영수증·공개 결과를 각각 확인한다. 이 문서를 작성한 시점에는 미래 정산을 검증할 수 없다.

## 3. 다음 후보 전환 조건

비활성 후보는 [`config/weekly-match-next.json`](../../../../config/weekly-match-next.json)이다. 현재 workflow가 읽는 파일은 계속 `config/weekly-match.json` 하나이며, 후보는 자동 소비·전환되지 않는다.

후보 일정은 기준일 **11/20**, 접수 마감 **11/23 09:00**, 종료 **11/27 18:00** 한국시간이다. 현재와 같은 은행 7종목·조선 5종목을 검토하며, 미래 종가를 미리 넣지 않는다.

11/16에 [KRX 거래시간·휴장 규정](https://global.krx.co.kr/contents/GLB/06/0602/0602020204/GLB0602020204T1.jsp)과 [공식 공지](https://open.krx.co.kr/contents/OPN/05/05000000/OPN05000000T1.jsp)를 재확인했다. 10/1~11/16 공지 제목 검색에서 거래시간 변경은 기존 11/19 수능 공지 1건, 휴장은 0건이었다. 이 범위에서 후보 주는 월~금 5개 정규장 09:00~15:30이며 이후 긴급 공지는 게시 전에 재확인한다. KIND 기업일정 조회는 접근 실패와 점검 안내 응답으로 실제 자료를 얻지 못해 중단했다. 기존 수집기의 split·기준가격 변경 감지는 전체 기업행사 확인을 대신하지 않으며, 현금배당 이벤트는 해당 플래그에 포함되지 않는다.

전환 담당은 다음 조건을 모두 확인한다.

1. 현재 대진의 최종 결과와 정산 근거를 확인했다. `pending`이면 후보로 교체하지 않는다. 단일 runner를 교체하면 이전 대진의 재확인이 끊긴다.
2. 공식 거래일·임시 시간 변경과 12종목의 기업행사·거래정지 여부를 게시 직전에 재확인했다. 현재 기업행사 전체 확인은 미완료다.
3. 다음 기준일 18:00 이후 12종목 실제 기준 종가를 확보할 수 있고, 게시 시각이 접수 마감보다 이르다. 가격 결측이면 게시하지 않는다.
4. 실제 OAuth 복귀·개인 기록 조회를 확인했다. 다음 대진은 직접 링크로 정상 저장을 검증한 뒤 일반 참여 진입을 공개한다.

모두 충족한 뒤에만 후보를 활성 설정으로 옮기고 `enabled:true`로 바꾸며, 기존 workflow를 사용한다. 새로운 원본 artifact 이름은 라운드 ID로 분리된다. 게시 영수증과 공개 대진을 확인한 후에만 게시 완료로 기록한다. 후보를 놓치면 날짜만 기계적으로 연장하지 않고 새 주를 재검토한다.

## 검증과 다음 확장

이번 재검사에서 주간 매치 단위·API·UI 24개와 Python runner 12개, `pnpm exec tsc --noEmit`, `pnpm lint --max-warnings 0`, `pnpm exec next build`가 통과했다. build는 로컬 비밀값 자리표시자 대신 격리용 Supabase 주소·키를 명시했고, DB 다운로드 단계 없이 기존 SQLite로 실행했다. 빌드 중 해당 격리 주소의 연결 실패·기본 정책 사용 로그가 있었으므로 production 인증 연결의 증거로 쓰지 않는다. middleware 사용 중단 예정 알림도 남아 있다. 이 검사는 실제 사용자 OAuth·운영 선택 저장을 대신하지 않는다.

결과 공유 카드·공식 결과 아카이브는 최초 정산 검증 이후 진행한다. 실제 사용자 성과가 없는 상태에서 시즌 기록을 만들거나 검색 성과를 주장하지 않는다. GA·Search Console의 실제 보고서 접근과 유입·참여·재참여 측정은 별도 미확인 범위다. 현재 기준은 [운영 절차](weekly-match-live-operations.md)를 함께 따른다.
